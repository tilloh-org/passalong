# Sale status on items implementation plan

> **For Hermes:** Implement task-by-task with TDD and an independent correctness review before the PR.

**Goal:** Let owners mark an item as sold — with sale channel, sale date, and proceeds — and show the sale state in the item list.

**Architecture:** Additive schema migration on `items` introducing a `sale_channels` allowlist (mirroring `item_categories`), nullable sale fields, and derived sold-state rendering. Repository mutations stay tenant/owner-scoped like every existing method. UI keeps the single-page pattern: one "mark sold" form per item card.

**Tech stack:** SvelteKit server actions, better-sqlite3 additive migration, Vitest, Playwright.

---

### Task 1: Schema migration (TDD, legacy fixture first)

**Files:** `src/lib/server/collection-repository.ts`, `collection-repository.test.ts`

**Steps:**
1. Failing test with a pre-migration `items` fixture (no sale columns); assert the migration adds `sale_channel TEXT`, `sold_at TEXT`, `sale_proceeds_cents INTEGER` (nullable), preserves rows, keeps foreign_key_check clean, and stamps a new `schema_migrations` version.
2. Implement the migration following the `rebuildItems`-style table rebuild; apply after `migrateTenantScopedImageKeys`.
3. Fresh-DB `createSchema` gets the same columns so both paths converge; assert row counts survive re-open (idempotence).

### Task 2: Repository mutations and listing (TDD)

**Steps:**
1. Failing tests: `markItemSold(itemId, scope, { channel, soldAt, proceedsCents })` sets values; `unmarkItemSold` clears them; both reject cross-tenant; `listItemsForOwner` returns the fields; invalid channel/legacy proceeds rejected before insert.
2. Implement with `singleDatabaseRowChange` checks; validate channel against the allowlist, proceeds as non-negative integer, `soldAt` as ISO string.
3. Full repository suite green.

### Task 3: Server action + UI (TDD)

**Files:** `src/routes/+page.server.ts`, `+page.svelte`, `page-actions.test.ts`

**Steps:**
1. Failing action tests: anonymous → 401; cross-tenant/unowned item → 400 with fixed German message; valid owner submit → 303 and DB state updated.
2. `markItemSold` / (re-open via unmark) actions with Same-Origin + scope guard, fixed user-facing messages (no raw SQL errors, per convention).
3. Item card shows "Verkauft" badge + channel/date when sold; collapsed "Verkauf erfassen" section with channel select, date, proceeds input; re-open action.
4. Svelte check, build, targeted E2E extension (one sold-mark flow inside the core test).

### Task 4: Verify and review

**Steps:**
1. Full local gate: audit, unit, check, build, E2E, release flow, compose, diff check.
2. Independent read-only review (isolation, migration idempotence, message leaks).
3. Single PR `feat/sale-status` → `develop`; screenshot in PR comment per convention.

## Risks and boundaries

- Keep migration additive and idempotent; never touch existing rows.
- No statistics/aggregation yet — earning summaries are a later slice.
- No public stand page yet — channels are data-only for now.
