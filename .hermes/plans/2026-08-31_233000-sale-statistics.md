# Sale statistics implementation plan

> **For Hermes:** Implement task-by-task with TDD and an independent correctness review before the PR.

**Goal:** Show the owner aggregate earnings from recorded sales — total, per channel, and per month — inside the collection page, computed server-side from the sale fields introduced in the sale-status slice.

**Scope decisions**
- Statistics are owner-scoped via the existing session scope (same tenant isolation as all collection queries).
- Aggregation lives in `collection-repository.ts` as `getSaleStatistics(scope)` so it is unit-testable without HTTP.
- The UI renders a compact summary card above the item list; no new route.
- Out of scope: public stand page, charts, export.

**Tasks**
1. RED: repository test — statistics across multiple items/channels/months on a fresh DB; foreign scope yields zeroed statistics.
2. GREEN: implement `getSaleStatistics` with SQL aggregation (`COUNT`, `SUM`, `GROUP BY`) reading `sold_at`/`sale_channel`/`sale_proceeds_cents`.
3. RED: action/load test — statistics are exposed through the page load data and absent for anonymous requests.
4. GREEN: wire statistics into `+page.server.ts` load and render a German summary card in `+page.svelte` (total, per channel with German labels, per month with `toLocaleDateString`).
5. E2E: extend the core flow to assert the summary card after recording a sale.
6. Full verification + screenshot + independent review + PR.

**Verification gates (same as previous slices):** `npm test`, `npm run check`, `npm run build`, `npm run test:e2e`, release-flow suite, compose config, diff check.
