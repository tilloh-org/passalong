# F-008 — The reference archive proves the takeover

Replaces: nothing
Implemented: PR #81 (2026-10-18)

## Goal

The importer is implemented, but its phase-5 exit gates were only proven against archives that a test
built in memory a moment earlier. This slice commits one complete, generic reference archive and
proves the gates against exactly those bytes: record counts before and after the import, media
checksums, tenant isolation across every table, the administrator selection with its sign-in, and
the two password-hash paths. It also names the source product as provenance only, so product copy,
routes and the exchange contract carry no identifier of the application passalong replaces.

## Functional requirements

- FA-1: `fixtures/exchange/reference-archive.zip` is a valid archive of the exchange format: three
  users with three tenants, a published and an unpublished stand, sold, reserved and open articles,
  several images per article, an avatar, market days with and without a linked day, expenses in
  several categories, one compatible legacy hash, one unsupported hash, and a manifest that declares
  the counts and a checksum for every entry.
- FA-2: The archive validates without a single finding, and every declared checksum and size matches
  the bytes it describes.
- FA-3: Importing the archive into an empty instance reproduces every declared count one to one
  (users, tenants, collections, items, market days, sales, expenses), and stores every media file
  with the bytes the manifest describes.
- FA-4: After the import no table contains a tenant-scope violation: every collection, item, image,
  market day, expense and role resolves to a record of its own tenant.
- FA-5: Exactly one imported account holds the instance admin role and can sign in with the password
  the takeover set; a second owner signs in with the password behind the carried-over hash and sees
  only their own articles.
- FA-6: The compatible legacy hash is replaced by the current format on the first successful
  sign-in; the unsupported hash is never stored and the account is marked for a password reset.
- FA-7: An archive whose media payload no longer matches its checksum is refused before activation
  and leaves the empty instance unchanged.
- FA-8: The source product is named only in documented provenance notes (design reference, icon
  source, a sample of a foreign hash format); product copy, routes, the exchange contract and the
  importer carry no identifier of it.

## Non-functional requirements

- NFA-1: Every proof runs against the committed file, not against an archive assembled inside the
  test; the same file is uploaded through the takeover dialog on a phone-sized project.
- NFA-2: Regenerating the archive is an explicit, documented command; a test run never rewrites a
  committed fixture.
- NFA-3: The archive needs no new dependency: it is a stored-only ZIP built by the existing writer.

## Technical constraints

- The archive lives at `fixtures/exchange/reference-archive.zip` and is generated by
  `src/lib/server/exchange-reference-archive.test-helper.ts`; the shared path and account names live
  in `src/lib/exchange-reference.ts`, which has no application imports so the E2E proof can use it.
- Regeneration: `REFERENCE_ARCHIVE_WRITE=1 npx vitest run src/lib/server/reference-archive.test.ts`.
- Images are real 8 × 8 RGB PNGs, so the archive stays usable if media validation is ever applied to
  imports.
- The Playwright takeover proof reads the instance database only to observe the stored hash, which
  the browser cannot show.

## Security level

before: 3 · after: 3

The slice adds no endpoint and widens no scope; it proves the existing takeover refuses damaged
archives and keeps every imported record inside its own tenant.

## Out of scope

- Format migrations for older archive versions.
- A producer tool that converts another application's data.
- A delta or repeated import.
- Deleting the provenance notes that name the source product.
